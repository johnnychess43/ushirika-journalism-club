# Ushirika Journalism Club — Flask edition

This repository now contains a Flask web application with a database-backed newsroom, role-based accounts, article review, events, forums, meeting minutes, gallery uploads, a treasurer workspace, and developer controls.

## Deploy on Render

1. In Render, create a **Blueprint** from this repository and review `render.yaml`.
2. The blueprint defines a Python web service, a managed PostgreSQL database, and persistent storage for uploaded files. The `starter` plans and persistent disk are paid Render resources; review current prices before creating them.
3. Add the following private environment variables in the Render web service:
   - `BOOTSTRAP_ADMIN_EMAIL`: the email address for the first developer account.
   - `BOOTSTRAP_ADMIN_PASSWORD`: a new, strong password for that account (do not reuse a password shared in chat).
4. Keep `SECRET_KEY` generated by Render. Keep `DATABASE_URL` and `INSTANCE_DIR` as configured by the Blueprint.
5. Deploy and open `/health`; it should return `{"status":"ok"}`.
6. Sign in using the bootstrap email and password, open **Developer tools**, and approve verified account requests.

The first developer account is created only when `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` are set and no developer account exists yet. Passwords are hashed before they are stored. Changing these environment variables later does not reset an existing account's password; use a dedicated password-reset workflow for that.

## Local development

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

Set a stable `SECRET_KEY` and a private bootstrap email/password before running:

```bash
# PowerShell example — use your own unique values:
$env:SECRET_KEY = "replace-with-a-long-random-secret"
$env:BOOTSTRAP_ADMIN_EMAIL = "your-admin-email@example.com"
$env:BOOTSTRAP_ADMIN_PASSWORD = "replace-with-a-new-strong-password"
$env:COOKIE_SECURE = "false"
python app.py
```

For production, use HTTPS, keep `COOKIE_SECURE=true`, use Render's PostgreSQL database and persistent disk, and never commit environment secrets.
